### Reproduce the renderer sandbox

With Docker available, build from the repository root. Image/dependency installation uses the network; the test execution below does not. The Docker context allowlist includes only tools, style, requirements and Python tests. It excludes recordings, weights, local environments and project work.

```bash
docker build -f tests/Dockerfile.smoke -t interview-skill-smoke .
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=1g \
  --cap-drop ALL --security-opt no-new-privileges --user 1000:1000 \
  interview-skill-smoke

docker run --rm --network none --read-only --tmpfs /tmp:rw,size=1g \
  --cap-drop ALL --security-opt no-new-privileges --user 1000:1000 \
  interview-skill-smoke python tests/smoke_public_workflow.py \
  --work /tmp/public-smoke \
  --font /usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc \
  --font-family 'Noto Sans CJK JP'
```

The second command series removes its temporary outputs when the container exits. To inspect results, use a dedicated writable output mount and set --work inside it. The smoke report explicitly records `asr_tested=false` and human review pending; fixture approvals are not real production approvals.

The first Docker Hub base-image request timed out during anonymous-token retrieval. The run recovered using the locally available `python:3.12-slim-bookworm` image; Debian packages and Pillow installed successfully. This was an environment/network failure, not a passing build. The checked-in recipe was then rebuilt and checked separately.

The public-workflow smoke also runs in GitHub Actions alongside the 13 regression tests. It proves toolchain behavior under the listed fixtures, not a fully autonomous interview editor.
