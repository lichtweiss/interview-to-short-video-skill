# 项目上下文：用户提供事实，技能整理与查缺

本文件是待批准的通用说明草案；不包含作者项目的私人资料。

最少需要：人物与组织名称/角色、采访发生的背景、受众与发布目的、关键术语及可公开边界。直接提供已有采访提纲、项目介绍或简短回答即可，不要求先建知识库。技能应先读取现有资料，指出真正影响当前判断的缺口，避免把填表变成启动门槛。

可选提供品牌规范、项目理念、历史作品和不希望出现的表达。这些有助于主题命名、术语校订及受众适配，但不允许覆盖受访者原话、删掉限制条件或虚构组织立场。品牌资料和录音有冲突时保留差异并询问，不自动“纠正”原声。

可在项目目录维护一份 `project_context.md`，包含：

- 名称、角色与确认来源；不确定的身份显式标注。
- 采访背景、受众、用途与拟发布渠道。
- 专有名词、已确认纠错及相关资料路径。
- 品牌/视觉选择，以及本次可公开与不得公开的边界。

上下文不足仍可基于原声转写、整理主题候选与制作中性标题。不能凭空补写人物身份、商业关系、宣传结论或组织态度。最小背景与真实素材由使用者提供；收集、结构化、查缺和处理不确定性属于技能工作。
