# 画面文字编订与字幕控制

完成初步转写、主题归类与候选选段后，在文字合成/批量生产之前建立 `画面文字编订.md`，先作为正式制作前的文案确认单交给用户。主动交付可点击的绝对文件路径，说明这一步等待用户编辑确认。请用户填写或确认：片名与副标题、受访者及场景说明、底部账号/机构角标。章节文案可在选段后补充。用户已提供或已授权沿用的直接预填；缺失信息不要擅自虚构。底部角标默认必填；用户明确要求不显示时才写 `[留空]`，避免把未确认状态静默渲染为空。用户编辑确认后才 apply 和渲染；若用户明确接受初稿并授权直接生产，可以使用 --accept-default，仍须以 --approval 记录真实授权来源。无回复不算默认接受；这份文档是项目维护入口，不要求塞进只含 MP4 的最终发送文件夹。逐字稿不混进这份固定文案表。

文案确认必须有可追踪的 `revision_id`（例如 `copy-20261016-r1`），并在编辑计划的 `copy_confirmation` 中记录用户确认状态。章节标签、顶部角标和底部角标按片逐条检查，不能把一条样片的统一角标当成整批已核对。人物名必须来自已经确认的 `identity_map`；用户纠正过的旧名称不得重新出现在标题、说明、角标或人物字段中。

文档是长期编辑入口；JSON 只作为素材时间及合成配置的机器载体。文案变动后重新编译到新的规格文件再渲染。更换文案不重新跑语音识别，也不改源切点。

```bash
python3 /path/to/skill/scripts/copy_sheet.py export /project/cuts.json /project/画面文字编订.md
# 用户修改文档最后一列。然后：
python3 /path/to/skill/scripts/copy_sheet.py apply /project/cuts.json /project/画面文字编订.md --out /project/build/cuts_compiled.json --approval "用户确认的原话或消息引用"
```

支持单条规格 JSON 和多条规格数组；可以导出兼容旧版的 `copy.json` 数组。附带渲染器对编译后的多条数组使用 `--id 01` 选择片段，每条使用独立输出目录。旧项目渲染器对新增字号和配色字段未必支持，需检查并接入这些参数；不要声称改了文档就自动更新了尚未重导的视频。

每条含标题、副标题、章节、中间说明、底部角标、6类字号、强调色和选色依据。主字幕正文仍在 SRT；字幕字号在此表维护。颜色在没有指定品牌或参考时先用 `suggest_palette.py` 提供素材候选，再把选定色填入文档。文档确认完成后保留在项目工作目录，最终 `v1` 文件夹可只包含 MP4。文案确认只表示固定文字版本已锁定，不表示身份、声音、语义或画面已经人工验收。

工具保留源规格指纹以防把新时间线覆盖回旧稿；若源切点后来改变，应先合并文案与新规格，再重新导出文档。每次编译输出带文档路径及指纹，方便确认成片使用哪一版文案。重新渲染前检查文档指纹仍一致。

画面文字最终烧入 MP4，修改文档后需要重导 MP4；SRT、ASS 和文案文档本身一直可编辑。不要把“有可编辑文档”描述成已导出的 MP4 内部文字可以直接改。

## 用户明确接受第一版

```bash
# 仅在用户明确授权“接受初稿，直接生产”后执行；不能由助手替用户决定。
python3 /path/to/skill/scripts/copy_sheet.py apply /project/cuts.json /project/画面文字编订.md --out /project/build/cuts_compiled.json --accept-default --approval "用户接受初稿并授权生产的实际消息引用"
```

`copy_approval.mode` 区分 edited-confirmed 与 default-accepted，`evidence` 保存授权来源。状态字段是工作流记录，不是身份认证或数字签名；调用者仍须忠实记录用户的真实决定。自动测试使用虚构确认，只验证程序分支。

apply 同时记录当前 SRT 的 SHA-256（文件内容指纹）。之后修改逐字字幕，渲染器会要求重新 apply；修改标题不会擅自改动 SRT。字幕改动影响尾句或时长时，还要重新核对 speech_end、章节与源切点。每次重新导出都要重新听看受影响部分。
