# 采访短视频验收矩阵

实际制作中需要防范四类断点：身份没有锁定、对话被按人物拆碎、章节/角标没有逐条验证、机器状态被误写成人工交付。下面把断点对应到证据和阻断动作。

| 风险 | 必须保留的证据 | 阻断条件 | 通过后才能做什么 |
|---|---|---|---|
| 人物身份混淆，或把未说话的人当发言人 | `identity_map`、原声/口型/画面位置证据、确认人 | 任何正式片使用未确认人物键；名称与用户纠正不一致 | 进入正式文案和渲染 |
| 对话被机械拆成个人片 | `topic_id`、发言顺序、关系类型、选段理由 | 用人物配额选片；多人片没有互动摘要；全景/双人方案未比较 | 锁定候选时间窗和布局 |
| 说话人贴边或错误硬裁切 | `layout`、`composition.evidence`、`crop_evidence` | 单人不居中；互动被裁掉；左右 crop 没有素材证据 | 生成正式规格 |
| 顶部角标永远是一段 | 每条章节表、每段语义依据、批次章节审计 | 章节是占位编号/比例；全批单段却没有逐条解释 | 合成 PNG/ASS 和进度条 |
| 标题/角标未经确认或批量错位 | 文案确认单、`revision_id`、最终 MP4 抽查 | `copy_status` 仍是 draft；角标统一套一段；文案表与规格指纹不一致 | 正式渲染和对外发送 |
| 把机器 QC 当成最终验收 | `machine_qc` 与四项 `human_review` 分开 | 有 pending 仍宣称正式交付；只看文件存在或日志 | 更新 delivered 状态 |
| 多个索引互相矛盾 | `state.canonical_manifest` 和冲突清单 | 正式数量、组别或状态在两个入口不同 | 继续返修或交付 |

## 状态解释

- `candidate`：只有候选选段或粗转写，不应对外发送。
- `preview`：可供审阅的样片/粗剪；可有 pending，但不能把名称、章节和文案确认状态写成已完成。
- `formal`：编辑计划、固定文案、技术检查和人工审阅均完成，准备进入交付目录。
- `delivered`：正式文件已放入本轮交付入口，并且交付清单与 canonical manifest 一致。

机器检查只覆盖规格、解码、时长、字幕时间、文件完整性等可测事实。身份、意群、对话关系、画面审美和收尾仍需要实际观看与听审；没有做过的项目保留 `pending`。
